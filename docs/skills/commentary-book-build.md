# Commentary book build

Use for David's translated-commentary series (Ibn Ezra), when starting a new parasha or rebuilding a draft. Where each parasha stands (pages, status, the next first page) is kept only in book.json: `python3 -I scripts/series_status.py` prints it. Never copy those numbers into a skill or a note.

Load **commentary-house-rules** first. It holds the standing rules (translation, Hebrew letters, misprint form, transliteration, Hashem, place names transliterated, only answered review rows) and the page look: verse band, section marks, Hebrew then English commentary, notes, the glossary strip at the foot of each page, front and back matter. This skill adds only how the book is built. Making a parasha final is the **finalize-parasha** skill.

**Nothing in the book changes until David answers it in a review list.** A change he asks for in chat, or one Claude suggests, becomes a new review row (with its explanation) and is applied only after he says the review is done (David, Oct 2026). A trial build to measure a change is fine, but don't commit or send it as the draft.

## Markup in the model (rendered by render.py)
- {b} bold, {i} italic, {h} Hebrew span, {hb} bold Hebrew lemma, {sc}/{sci} small caps, {s}(reference){/s}, {k} key term, {lem} lemma, {v} a vowel sign shown on an alef ({v}אָ{/v}).
- {w}hebrew{g}gloss{/g}{/w} for a Hebrew example with its English gloss inside English text.
- Grammar examples get the larger English word on the word(s) that carry the point (see scripts/f2_english.py).
- An unknown tag stops render.py with "unknown tag": add it to TAGS there.

## Pipeline (project layout: data/, scripts/, fonts/, build/)
1. **Extract** the source PDF's lines to data/book_lines.json. `scripts/parse_book.py` splits them into flows (verse English, Hebrew commentary, English commentary, notes, front/back matter) → data/flows.json.
2. **Hebrew check.** `scripts/fix_hebrew.py` compares the Hebrew commentary letter-for-letter with Sefaria's text and fills letters lost in the PDF text layer (U+FFFD). Never change a real letter; only restore missing ones, and list the differences for review. Sefaria shares this edition's misprints, so this step finds missing letters, not misprints. For misprints use commentary-misprint-finder.
3. **Model.** `scripts/build_model.py` assembles data/model*.json, with keys verses (dicts: ch, v, he, en, brk = פ/ס section mark or null, aliyah), aliyot, hc, ec, notes and front. ec and notes are lists of dicts with ch, v, text (chapter-header blocks have kind 'chapter' and no text). The current Bereshit model is data/model_final5.json; edit it in place with a Python read-modify-write (json.dump with ensure_ascii=False, indent=0 keeps the file's format and a small git diff), after a backup copy, and log every change.
4. **Front matter.** bereshit/data/front.json (keys before / after, each a list of pages with html) is the source: edit it directly with the same inline markup as the model. scripts/front_src.py is out of date and must not be rerun. The front matter is its own file, pages i–x (title page, contents, preface, how this edition was made, key to terms, note on the vowels): `cd bereshit && python3 scripts/render.py data/model_final5.json build/front.html frontonly && python3 scripts/make_pdf.py "$PWD/build/front.html" "$PWD/build/front.pdf" build/frep.json`, copied to `front/Ibn Ezra on the Torah - Front Matter.pdf`. Its contents page is generated from book.json and lists every final parasha. Each key-to-terms entry ends with "First:" and its first place in each parasha (review_round/key_places.py, key_verify.py, apply_key.py).
5. **Render.** `python3 scripts/render.py <model.json> build/book.html` converts the markup to HTML, hyphenates the English with pyphen (soft hyphens: strip \xc2\xad before searching pdftotext output), embeds the fonts and applies book.css.
6. **Paginate and make the PDF.** `python3 scripts/make_pdf.py "$PWD/build/book.html" "$PWD/build/book.pdf" build/rep.json` (absolute paths; about 30–45 s). Page numbers start at `first_page` in the parasha's parasha.json, and the running heads come from it too. Chromium (Playwright, preinstalled; don't run playwright install) loads the page, `layout.js` plans each page (verse band, Hebrew, English, notes; fixed line heights and gaps) and writes the JSON report (first_page, last_page, log, report, console). Every parasha uses the Noach layout (Noach List 2 B1): notes stay on their verse's page (NB 100), no chapter numbers in the notes, a new paragraph at each chapter; STRETCH 0.15, which David doesn't want tightened further. The verse band prints each verse's פ/ס mark after it (`.band .brk` in book.css). A layout change can be checked without making a PDF by loading build/book.html in Playwright, waiting for document.title === 'READY', and measuring the DOM.
7. **Check.** `python3 -I scripts/check_all.py <folder>` (repo top) runs every check in one go — letters against Sefaria, vowels, misprint scan, check_book's house-rule and layout report, every (printed) [correction] has its Text line, every Onkelos entry is in the model, ה׳ (not ד') in the English, every Hebrew span in the comments and notes traced to its source ("Hebrew sources", scripts/source_check.py) and no marker left unresolved, page numbers against book.json and parasha.json, and whether the build is older than the model — and lists only NEW hits; hits already read are in `<folder>/review/check_baseline.json`. Read every new hit, fix or make review rows, then run it again with `--accept`. A script that cannot run is reported as failing, never as ok. Also `python3 -I review_grammar/all/clean.py --check`. Then verse against comment: dump every verse with its English comments (and read the notes) and compare, as the house rules say. Also compare the verses' brk marks with Sefaria's Miqra according to the Masorah ({פ}/{ס} in its text; `/api/v3/texts/Genesis.1-6?version=hebrew|Miqra according to the Masorah`): the count and the places must match (Bereshit: 23). Read every hit before going on. After pushing, look at the GitHub check run (`gh run list -R davidross01/ibn-ezra-commentary -L 3`): it runs check_all on every parasha, so a change for one parasha can turn another red; a red X is read and fixed the same session.
8. **Look.** Find pages by text with pdftotext (split on \f, strip \xad), rasterize a few with pdftoppm (the start, a page with פ/ס marks, a chapter break, the densest page, every page touched by a change, the end) and view them. Check that each commentary starts on or after its verse's page, that no divider is orphaned, that the Hebrew RTL is intact, that the English and Hebrew of the verse band start on one line, and that Hashem is in small caps.
9. **Deliver.** Copy build/book.pdf to drafts/"<Commentator> <Parasha> - draft N.pdf", send it with SendUserFile, and give the page count, the page numbers (A–B) and what changed. After the push (step 10), put it in the Drive folder too: `refresh_drive()` in the Composio workbench (scripts/workbench/wb.py) adds the newest draft to "05 Drafts" — every draft, not only finals (missed for Chayei Sarah draft 1, David, 2 Nov 2026). The final ("- final.pdf", with any "Draft for review" removed) is made by finalize-parasha.
10. **Back up to GitHub.** `git pull --rebase` first (archives may have been committed from the workbench), then commit the changed data, scripts, the new PDF and the applied-rows log (review_round/applied_rows*.json or review/draftN_applied_rows.json), update book.json (this parasha's first and last page, status, `next_first_page`) and the History in README.md, with a one-line message ending with the session's attribution lines, and push to main. build/ and test/ of each parasha are in .gitignore.
11. **Parts export — only when the parasha is final** (David, Oct 2026): `python3 scripts/export_parts.py` at the repo top writes the parasha's five parts — chumash_hebrew, chumash_english, ibn_ezra_hebrew, ibn_ezra_english, notes — to `<parasha>/export/` as .txt (plain, headed by verse, chapter headings, aliyot and פ/ס) and .json (ref, ch, v, plain text, the book's markup; part numbers for several comments or notes on one verse; Hebrew verses also without cantillation), plus a README with the counts, and rebuilds the book-wide set in `export/` from every final parasha in order. If a final parasha's model is not data/model.json, add it to MODEL in the script (Bereshit: data/model_final5.json). Check that the counts in the export README match the model. Never export a draft.

## A parasha translated from Sefaria (Noach on)
Noach and later parashot have no source PDF: the text comes from Sefaria and the translation is written fresh. Layout in the parasha folder:
- src/: torah_raw.json (Genesis with MAM footnotes, e.g. the Sephardi/Ashkenazi spellings at 7:11 and 9:29), ie.json (Ibn Ezra per verse: he[] segments, en[]), rashi.json, radak.json, ramban.json, rashbam.json, onkelos.json; tanakh.json (copy the repo-top src/tanakh.json: all 39 books, MAM, for the vowel check and {q:} quotations); data/verses_he.json (ch, v, he with cantillation, brk; a ketiv/qere prints the reading).
- work/chN.py, one per chapter: V {(ch,v): English verse}, HC {(ch,v): pointed Hebrew commentary}, EC [((ch,v), English comment)], N [((ch,v), note)]. Keep the authored order inside a verse. Review answers are applied in these files with review_round/subs.py (`sub(files, old, new, row_id)`: exact once, handles the \" escapes of .py sources, idempotent, logged with `save(...)`); write one apply script per review round in review_round/.
- `python3 work/assemble.py` → data/model.json (aliyot, 'first' flags, chapter markers for every chapter after the first, the Onkelos lines from work/onkelos.py, and every `{q:Book ch:v:i-j}` / `{o:i-j}` marker in the chN.py comments and notes resolved by scripts/onk_lib.py; it stops on a missing verse or a bad marker). From Chayei Sarah on, Hebrew quoted in EC and N is written as a marker, never typed (copy vayera/work/assemble.py, which has the hook; `python3 -I scripts/onk_lib.py words "Book ch:v"` numbers a verse's words).
- Checks: `scripts/check_all.py <folder>` (step 7) runs consonant_check (must be differences: 0; `work/fix_letters.py` fixes vowel-letter differences in the chN.py files and lists the rest), vowel_check, misprint_scan and check_book, and the Text-line check. While writing one chapter, `work/check_ch.py` is the quick letter check.
- When a verse band wording changes, change with it the English comment's italic lemma that quotes the verse, and every note that says how the verse is translated ("the verse translation follows him" → "keeps the usual …"). Search the same Hebrew word in other verses too (אֵלוֹן at 12:6, 13:18, 14:13; רְכוּשׁ at 12:5, 13:6) and ask David before leaving one word translated two ways.
- data/front.json is {"before": [], "after": []} for a parasha inside the book.
- Write the review rows as data (review/list1_rows.py → `review/make_rows.py` → review/list1_rows.json): make_rows takes every Hebrew line from the model and checks the English excerpts against it, then the rows go to the Google Doc (review-list-google-doc; read them in the workbench from GitHub).

Everything lives in David's private repo **davidross01/ibn-ezra-commentary**: one folder per parasha (bereshit/, noach/, lech_lecha/, …), each with scripts/, data/, fonts/, lib/, ref/, drafts/, review/ (with archive/ for finished review docs, and check_baseline.json), export/ (once final) and a parasha.json; at the top book.json, README.md, review_docs.json (registry of review docs), docs/rules/ (the house rules in full), front/ (front matter PDF), book/ (the full book), insights/ (Key Insights booklets), export/ (book-wide parts), review_round/ (apply scripts and logs), review_grammar/ and src/ (tanakh.json: the whole Tanakh, MAM; rashi_genesis.json; talmud.json — the shared sources for checks and {q:}) and scripts/ (check_all.py, source_check.py, onk_lib.py, export_parts.py, publish_pdfs.py, review_doc.py, check_review_doc.py, series_status.py, workbench/wb.py).
- Start of a session: attach the repo (add_repo davidross01/ibn-ezra-commentary, push access) and clone it to /home/claude/ibn-ezra-commentary, then work inside the parasha's folder. If the repo can't be reached, the Claude GitHub app may have lost access to it: ask David to add the repo under github.com/settings/installations → Claude → Configure → Repository access. From the Composio workbench, GITHUB_COMMIT_MULTIPLE_FILES and GITHUB_GET_RAW_REPOSITORY_CONTENT on David's account also reach it (scripts/workbench/wb.py wraps them).
- parasha.json: parasha, sefer, verses, first_page, run_en and run_he (running heads, e.g. "BERESHIT/GENESIS — PARASHAT NOACH" / "בְּרֵאשִׁית – פָּרָשַׁת נֹחַ"), title, and volume_front_matter (false: the title page, preface and key to terms are the separate front matter).
- parasha.json may also carry heading_en / heading_he (e.g. "PARASHAT NOACH" / "פָּרָשַׁת נֹחַ"): layout.js then gives the first page 74 px less room (HEAD) and draws the heading there (.phead in book.css), with the verse range from "verses". When the parasha starts mid-chapter, the first verse of the band shows its chapter (6:9, [ו] ט).
- book.json: one entry per parasha with folder, first_page, last_page and status ("draft N (…)" or "final (…)"), plus next_first_page. The full book `book/Ibn Ezra on the Torah - Bereshit to <last final parasha>.pdf` (front matter + every final parasha) is rebuilt only when a parasha becomes final, by `python3 scripts/publish_pdfs.py --rebuild`.
- If a parasha's page count changes, update its last_page and renumber every later parasha (change their first_page and rebuild), so the numbers stay continuous; check_all's pages check confirms it. Tell David which parashot moved.
- Page sides follow the number (odd = left running head in English), so continuous numbering also keeps facing pages right.

## New parasha
1. Make a new folder in the repo for it (copy the scripts/ stubs, ref/ and data/foot_terms.json from the last parasha; the stubs run the shared scripts in shared/, which hold the fonts and lib too — David, 9 Nov 2026; Bereshit alone keeps its own scripts), write its parasha.json with first_page = book.json's next_first_page and volume_front_matter false, bring in the text (source PDF, or Sefaria as above) and rerun the steps. Make sure each verse's `brk` (פ/ס) comes over from the source and matches Sefaria, so the section marks print.
2. From draft 1: place names transliterated (Ur Kasdim, Mitzrayim, Kena'an …; the person Haran stays Haran), the Hashem and Elohim rules, ה׳ for the Name in the English, the Onkelos lines (commentary-onkelos-notes), and the grammar-note style (what a reader would think, what Ibn Ezra shows, what it does for the word).
3. Run commentary-misprint-finder (or scripts/misprint_scan.py) on the new Hebrew.
4. Run the verse-against-comment sweep before draft 1, so the verse band follows the commentator from the start rather than through review rows.
5. Build a new review list for the parasha (review-list-google-doc skill, with its Explanations tab) of misprints, translation choices, verse-against-comment places (one row per verse), grammar points you are unsure of, layout questions, a Place names row listing every place name for David to look over, and the names of people, one row each with its alternative spelling (Rebekah / Rebecca). One row per item: never several misprints or changes in one row (David, 2 Nov 2026). Names David has confirmed (docs/rules/confirmed_names.json) are not asked again (5 Nov 2026). The list also has the **Ideas Part** (ibn-ezra-idea-notes): one row per idea paragraph, Now = the note without it, Alternative = with it, with a Saadia sentence and a short pointer to Ibn Ezra's own writings inside it where they add something (David, 9 Nov 2026; model: Toledot List 1 Part F as rebuilt on 9 Nov). Where Now and Alternative render Hebrew, the Now box opens with that Hebrew (make_rows does it; 8 Nov 2026). Every idea sentence is checked against its source first (scripts/cite_check.py), and the Consistency Review (review_audit/consistency/) is run again for the phrases the new parasha repeats (9 Nov 2026). Build the doc with `Builder.run(cfg)`. Send it with draft 1. Carry over open items from the last parasha only as David chooses.
6. After each draft, back up to GitHub (step 10), add the parasha to book.json, and run refresh_drive() so the draft is in Drive. When every review is answered and applied, run finalize-parasha.
